# neutron-email-triage

Jev-first email classification for Proton Mail via Proton Mail Bridge. This
independent React + TypeScript + Electron application also provides a CLI. The
React renderer is bundled with Vite; Electron and CLI TypeScript are compiled
into `dist/`.

Neutron Email Triage is an independent, unofficial project and is not
affiliated with or endorsed by Proton AG or TypeSafe AI.

**First-time setup:** see [Setup and configuration](#setup-and-configuration)
before launching a scan, including when using the Windows installer.

## CLI contract (source of truth)

All GUI actions are backed by these CLI commands:

- `npm run run -- [flags]` — triage run (dry-run by default)
- `npm run scan -- [flags]` — alias of run
- `npm run history` — recent decision log entries
- `npm run health` — environment/config health checks
- `npm run config` — runtime config (secrets masked)
- `npm run move -- --uid <uid> --destination <trash|archive>` — move one inbox message

Common flags for `run`/`scan`:

- `--limit <n|all>`
- `--offset <n>`
- `--include-body`
- `--unreadonly`
- `--reclassify`
- `--execute --trash-threshold <0.9..1.0>`
- `--json`

## GUI (Electron MVP)

Build the TypeScript sources and run:

```powershell
npm install
npm run build
npm run electron
```

To build a Windows x64 installer, run:

```powershell
npm run dist:win
```

The NSIS installer is written to `release/` as
`Neutron Email Triage-<version>-Setup.exe`. It installs per-user by default and offers
a custom installation-directory option. The packaged app stores decision
history in the user's application data directory rather than inside the
read-only application bundle. Proton Mail Bridge and TypeSafe API credentials
must be configured separately on each computer.

The CLI and Electron entry points run from the generated `dist/` directory.
Use `npm test` to build and run the test suite.

Storybook stories and browser interaction tests are available with:

```powershell
npx playwright install chromium
npm run test:storybook
```

The Storybook test command runs the interaction tests in Chromium without
starting the Storybook UI. Use `npm run storybook` to browse components.
`npm run test:all` runs the build, Jest tests, Node tests, and Storybook tests.
Each component lives in its own folder under `renderer/components`; Jest tests
are colocated in that folder's `__tests__` directory.

To build a Windows x64 installer, run:

```powershell
npm run dist:win
```

The NSIS installer is written to `release/` as
`Neutron Email Triage-<version>-Setup.exe`. It installs per-user by default and offers
a custom installation-directory option. The packaged app stores decision
history in the user's application data directory rather than inside the
read-only application bundle. Proton Mail Bridge and TypeSafe API credentials
must be configured separately on each computer.

GUI surfaces:

- Health panel -> `health --json`
- Config panel -> `config --json`
- Run panel -> `run ... --json`
- History table -> `history --limit N --json`

Health, config, and history share handlers with the CLI. Runs use an isolated
worker process. Electron launches its executable with `ELECTRON_RUN_AS_NODE=1`
so it runs the worker as Node, rather than opening another Electron app.
`--json` returns one JSON response; diagnostics go to stderr. Failures return a
nonzero exit code and an error response or a run summary with failure counts.
The desktop worker has a five-minute limit and is stopped if it exceeds that
limit. A stopped run may have partially processed mail; review history before
retrying.

The Health, Config, and Run panels each offer a human-readable **Rich UI** view
alongside the corresponding JSON output. In Run, both tabs show the same result
without rerunning the scan. Each recommendation includes the message date,
subject, sender, confidence, Jev decision, and action status. Action status is
shown as **Pending Decision** until a move is recorded. Trash and archive
actions are confirmed individually and do not require rerunning the scan; JSON
output can be copied to the clipboard.

## Safety

- Dry-run is default
- `--execute` requires `--trash-threshold >= 0.9`
- Per-message trash/archive actions require individual confirmation
- Decision log is local (`decisions.jsonl`)

## Setup and configuration

### 1. Install and sign in to Proton Mail Bridge

Install [Proton Mail Bridge](https://proton.me/mail/bridge), sign in to your
Proton account, and keep Bridge running while using Neutron Email Triage.
You need a Proton plan that supports Bridge.

In Bridge, select the account you want to triage and open its mail-client
configuration details. Copy the **IMAP** hostname, port, username, and password.
Use the credentials generated by Bridge, **not your regular Proton account
password**, and use the IMAP port rather than the SMTP port.

Bridge must run on the same computer as Neutron Email Triage. Keep the
connection on the local loopback address; this application's Bridge connection
accepts Bridge's self-signed certificate and is not intended for remote mail
servers.

### 2. Get a TypeSafe API key

Create an API key through [TypeSafe AI](https://typesafe.ai) for access to the
Jev classification service. Keep the key private; do not put it in an issue,
screenshot, or committed file.

### 3. Configure environment variables

The app reads these values from the environment when it starts. It does not
automatically load a `.env` file, and installing the app does not configure
these values for you.

| Variable | Required? | Value |
| --- | --- | --- |
| `PROTON_MAIL_BRIDGE_HOSTNAME` | Optional | IMAP hostname shown by Bridge; defaults to `127.0.0.1`. |
| `PROTON_MAIL_BRIDGE_PORT` | Optional | IMAP port shown by Bridge; defaults to `1143`. |
| `PROTON_MAIL_BRIDGE_USERNAME` | Yes | Username shown in Bridge's mail-client settings. |
| `PROTON_MAIL_BRIDGE_PASSWORD` | Yes | Password generated by Bridge, not your Proton account password. |
| `TYPESAFE_AI_API_KEY` | Yes, for classification | Your TypeSafe AI API key. |
| `NEUTRON_EMAIL_TRIAGE_LOG` | Optional | Full path to the CLI decision-history file. Defaults to `decisions.jsonl` in the project directory when running from source. The installed desktop app manages its own history location. |

#### Windows installer: persistent settings

Use **user environment variables**; system-wide variables and administrator
access are not needed.

1. Close Neutron Email Triage if it is running.
2. Open Start and search for **Edit environment variables for your account**.
   Alternatively, open **Edit the system environment variables**, then click
   **Environment Variables**.
3. Under **User variables**, click **New** for each required variable in the
   table. Enter the variable name exactly and paste its value without surrounding
   quotes. Add the hostname and port too if Bridge shows different values from
   the defaults.
4. Click **OK** to save and close the dialogs.
5. Open a new terminal if using the CLI, then launch Neutron Email Triage.
   If it still cannot see the new variables, sign out of Windows and sign back
   in before launching it again.

Environment variables are not an encrypted secret store. They are available to
programs running under your account; use a trusted computer and never share a
dump of your environment.

#### Running from source: current PowerShell session

Install Node.js 20 or newer. In a PowerShell terminal opened in the project
directory, replace the placeholders below with your own Bridge settings and
TypeSafe key:

```powershell
$env:PROTON_MAIL_BRIDGE_HOSTNAME = '127.0.0.1'
$env:PROTON_MAIL_BRIDGE_PORT = '1143'
$env:PROTON_MAIL_BRIDGE_USERNAME = '<username shown by Bridge>'
$env:PROTON_MAIL_BRIDGE_PASSWORD = '<password generated by Bridge>'
$env:TYPESAFE_AI_API_KEY = '<your TypeSafe API key>'

npm ci
npm run health
npm run electron
```

These assignments last only for that terminal session and programs launched
from it. They do not configure an app opened separately from a desktop shortcut.
Commands containing secrets may be saved in PowerShell history; use the Windows
user-variable method above if you do not want to type secrets into commands.
Do not save this example with real values in the repository.

### 4. Check the configuration and try a dry run

In the desktop app, refresh **Health** and **Config**. Check the connection
address and that the Bridge credentials and TypeSafe key are present. Password
and API-key values are masked in Config. Health checks configuration presence;
it does **not** test the Bridge connection or validate the API key.

Leave **Execute** disabled for your first scan and use a small message limit.
From source, you can run the equivalent CLI scan in the configured terminal:

```powershell
npm run run -- --limit 5
```

This is a dry run: it classifies messages and writes local decision history but
does not move mail. Sender, subject, and date are sent to TypeSafe for
classification. Message-body snippets are only included when you explicitly
enable `--include-body` (or the corresponding UI option).

If setup fails:

- **Missing environment variable:** check the variable names and restart the
  app or launch it from the terminal where the variables were set.
- **Connection refused:** make sure Bridge is running and signed in, and check
  its IMAP hostname and port.
- **Authentication failed:** copy the username and generated password from
  Bridge again; your normal Proton password will not work here.
- **TypeSafe API error:** check that the key has access to Jev and that your
  TypeSafe account has any required usage credit or quota.
